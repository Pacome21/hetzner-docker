Référence à appliquer sur le SERVEUR WireGuard (ex. 178.198.57.218), pas sur la machine Docker.

À vérifier / configurer
-----------------------
1) Forwarding IPv4
   sysctl: net.ipv4.ip_forward = 1
   (persistant: /etc/sysctl.d/ ou équivalent)

2) NAT pour le trafic VPN -> LAN 192.168.1.0/24
   Remplacez wg0 par l’interface WireGuard réelle du serveur et ajustez l’interface LAN (eth0, enp0s3, etc.).

   iptables (exemple indicatif) :
   iptables -t nat -A POSTROUTING -s 10.0.1.0/24 -o LAN_IF -j MASQUERADE
   iptables -A FORWARD -i wg0 -o LAN_IF -j ACCEPT
   iptables -A FORWARD -i LAN_IF -o wg0 -m state --state RELATED,ESTABLISHED -j ACCEPT

   Adaptez 10.0.1.0/24 au pool VPN réel du serveur.

3) Pare-feu
   Autoriser UDP 51820 entrant vers le serveur.
   Autoriser le forward entre wg0 et le LAN comme ci-dessus.

4) Peer client
   Côté serveur, le peer Home Assistant doit avoir une IP cohérente (ex. 10.0.1.5/32) et AllowedIPs
   côté serveur alignés avec ce que vous routez (souvent 10.0.1.5/32 pour le client).

ping vers une IP du LAN 192.168.1.x (voir test depuis conteneur sur la machine Docker).
